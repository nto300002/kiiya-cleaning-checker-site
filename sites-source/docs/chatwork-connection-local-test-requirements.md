# Chatwork本番接続のローカルテスト要件（Issue #11）

対象は本番送信元の登録、送信元確認、ルーム候補の確定まで。実際のOAuth認可、秘密値登録、実ルーム参照、投稿はブラウザ側の受け入れに残す。テストでは架空のID・トークン・ルームを使用する。

| ID | 条件 | 期待結果 |
| --- | --- | --- |
| CW-LOCAL-01 | OAuth接続の保存時に監査書き込みが失敗する／設定版が競合する | 設定・監査とも変更されない。異なる送信元IDなら再確認待ちになる |
| CW-LOCAL-02 | 送信元確定時に監査書き込みが失敗する／設定版が競合する | 設定・監査とも変更されず、二重確定しない |
| CW-LOCAL-03 | ルーム候補の確定時に監査書き込みが失敗する | 設定、候補消費、監査をまとめて取り消す |
| CW-LOCAL-04 | 候補が10分超、別操作者、別送信元、旧設定版、使用済み | 保存を拒否し、設定・候補・監査を変えない |
| CW-LOCAL-05 | ルーム確定に成功する | 取得した名前とIDを保存し、状態は`DestinationVerificationRequired`、送信可能はfalse |
| CW-LOCAL-06 | 本番設定行欠落／権限のない職員 | 設定APIは503／権限のない詳細・変更APIは403 |
| CW-LOCAL-07 | 一般職員が送信設定を読む | room ID、account ID、トークンを返さず、登録済みのルーム名と投稿確認待ちを示す |
| CW-LOCAL-08 | OAuth・ルーム照会中に設定権限を剥奪する | 操作開始時の職員版と保存時の有効状態・権限を照合し、設定・候補・監査を更新しない。剥奪後に再付与しても旧操作は拒否する |

実装順は失敗するテスト追加、実装、ローカルテスト・型検査・ビルドの順とする。Issue #11の完了には、別途ブラウザ側の受け入れ結果が必要。

## 2026-10-28 ローカル実行結果

- 先に追加した保存・監査テストは実装前にモジュール未作成で失敗。API応答とルームID照合のテストもそれぞれ実装前に失敗した。
- 架空のIDとトークンを使う全37件のテスト、TypeScript型検査、サイトのビルドが成功した。新規の保存処理・テストファイルはESLintも成功した。
- APIルートをローカルで実行し、CW-LOCAL-06・07の403／503／一般職員向け応答、およびルーム照会中・OAuthコールバック中の権限剥奪をHTTP要求・応答として確認した。OAuthで取得した送信元とトークンは剥奪後に保存されず、認可試行は使用済みになる。SQLiteアダプターでD1を模擬しており、実D1接続ではない。
- 実D1、Chatwork OAuth、実ルーム取得、公開Siteの画面操作、確認投稿は未実施。
