# Sites版の受け入れケース（設計段階）

案A（SiteがD1/R2とトークンの正本、Cloud RunがChatwork投稿・非同期実行）を採用方針とする。Issue #10の検証用ルームへの本文1件の接続疎通だけ実測済みであり、以下のケースは**その一部以外は未実施**。Issue #1では必要な最小内部契約だけを仮置きし、案Aで実装を続けられると判定した後、Issue #3でSites版OpenAPI・D1/R2スキーマ・配備コミットとの対応を固定する。APIを呼ぶケースは`operationId`、画面比較は画面IDと参照版、移行・復元は手順IDと証跡、外部配送は構成IDと実行ログへ対応付ける。対応表がないままIssue #9を合格にしない。元の[業務テストケース](baseline/test-cases.md)も引き続き適用する。

各ケースには`共有SHA／Sites配備版／Cloud Run配備版／日時／実行者／環境／対応するoperationId・画面ID・手順ID・構成ID／期待・実結果／合格・不合格・未実施／証跡／残課題`を記録する。`SITE-AUTH-02`は所有者移行手順、`SITE-D1-03`は退避・復元手順、`SITE-UI-01`は画面ID、`SITE-JOB-01/02/04/05/06/07/08/09`は配送構成と実行ログを主な対応先とし、呼び出すAPIがあればその`operationId`も併記する。Issue #10の実Chatwork投稿は固定した検証用ルームだけで行う。業務報告ルームの権限確認と本番送信は別ケース・別証跡で扱い、実施時の宛先・時間・承認者を非公開台帳へ記録する。案Bは採用していないためGCPをデータ正本とするケースは判定対象に含めない。案を変更する場合は対応するケースを先に定義し、D1/R2ケースを合格として流用しない。
