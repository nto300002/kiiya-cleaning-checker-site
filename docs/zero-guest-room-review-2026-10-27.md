# 宿泊なし・清掃ありの客室に関する変更レビュー（2026-10-27）

## 現場からの要望

客室を清掃対象に選び、宿泊人数を大人0人・子ども0人にした場合も、ベッドメイキングと部屋掃除は行う。次の客室チェック画面にアメニティの項目を出さない。

追加確認で、**0人入力は全ての客室種別で認める**こと、**0人時には枕の確認項目も非表示にする**ことが決定した。「連泊・アメニティのみ」で0人なら、対象室の記録と職員最終確認を残し、個別の客室チェック項目は不要とする。

## 現行Siteとの差異

- `lib/domain.ts`の`missingForReport`は、選択客室の宿泊人数が1人未満なら報告を止める。0人の清掃を完了できない。
- `roomCheckKeys`は0人でもスリッパと歯ブラシを返すため、客室チェックに表示され、報告必須にもなる。
- `targetRooms(..., "amenities")`は全選択客室を返す。ユニット1のアメニティセット作業も0人の客室を対象にしている。画面側にも同じ対象室判定があり、両方を揃える必要がある。
- 人数を変更したとき、ベッドメイクと職員最終確認は取り消すが、以前のアメニティ回答は残り得る。0人から1人以上へ戻した場合、旧回答を再利用しないようにする必要がある。
- 人数の変更でアメニティセットの対象室が増減しても、現在完了済みの作業状態が残り得る。対象室が増えた場合に旧完了を流用できない。
- 既存の未解消不備がアメニティ項目に紐づいていた場合、項目の非表示だけで不備を消したり報告を許したりしてはならない。

## 実装に必要な判定

1. 対象客室の大人＋子どもが0人なら「宿泊なし」と表示し、どの客室種別でも0人を入力エラーにしない。客室を対象から外す操作とは区別する。
2. 客室チェックのアメニティ項目と枕を非表示にし、完了条件から外す。宿泊人数に連動する数量・設置場所の説明も0人には表示しない。通常清掃・連泊清掃では、適用される清掃項目と職員最終確認を残す。「連泊・アメニティのみ」で0人なら個別チェック項目は表示せず、職員最終確認だけを必須にする。
3. ユニット1「アメニティセット」の対象は宿泊人数が1人以上の客室だけとする。全室0人ならその作業を非表示・報告必須条件から除外し、混在時は宿泊のある客室だけを対象として表示・報告する。
4. 人数を変更したら、以前の人数で回答した該当チェックと職員最終確認を再実施させる。非表示になった項目の旧回答は新たな完了判定に流用しない。アメニティ作業の対象室が増えた場合は旧対象での完了を新対象の完了として扱わない。
5. 未解消不備は項目が画面から消えても履歴と不備一覧に残し、解消まで報告を止める。解消操作への導線を失わせない。
6. 報告プレビュー・固定版にも0人の対象室と清掃種別が分かるよう記録し、0人客室をアメニティの対象室として表示しない。

## 受け入れ例

- 通常清掃・204号室・大人0人・子ども0人：ベッドメイクと部屋掃除、最終確認は表示。アメニティの客室チェックと同室向けアメニティセットは出ない。必要な清掃を終えれば報告可能。
- 連泊清掃・205号室・大人0人・子ども0人：既存の連泊清掃項目のうち、枕とアメニティ配置を除いた清掃項目を表示し、対象作業と最終確認の結果で報告を判定する。
- 連泊・アメニティのみ・203号室・大人0人・子ども0人：対象室として記録し、個別チェックは表示しない。職員最終確認は表示して必須にする。アメニティ作業の対象室には含めない。
- 通常清掃・204号室0人と206号室3人の混在：アメニティセットの対象は206号室だけ。204号室の清掃作業は残る。
- 1人以上でアメニティ確認済み→0人→1人以上：以前の回答をそのまま完了扱いにせず再確認する。
- 未解消のアメニティ不備を持つ客室を0人に変更：不備の履歴・解消操作・報告停止を維持する。
