# 運用・検証・受け入れ

## 環境

検証と本番のSite、D1、R2、シークレット、Cloud Runワーカー、Cloud Tasks／Scheduler、Chatwork宛先を分離する。GitHub publicリポジトリに職員氏名、画像、報告、room ID、OAuthクライアント秘密値、アクセストークンを置かない。Sitesのホスト済みシークレットで必要なキーだけ設定し、画面や通常ログへ出さない。

Issue #10のOAuth接続試験は例外として、既存の公開本番Siteで検証用Chatworkアカウント・ルームとD1の`chatwork_smoke`名前空間だけを使う。試験APIはサーバー側でSite origin、環境値、有効期限、IT権限、確定済みアカウントID、固定ルームIDを照合し、試験終了時に無効化する。本番報告の接続行・版・送信状態へ作用させない。詳細と実施前のリソース照合はIssue #10に従う。この限定試験を、分離した検証環境での統合受け入れやCloud Run投稿の代わりにしない。

検証環境では、認証・職員登録・退職者遮断、D1スキーマ変更とバックアップ／復元、R2の権限・一覧・削除、PDF・画像生成、Chatwork実送信、送信結果不明、遅延・定期処理、保存期限、旧版再表示を確認する。Siteとリポジトリの公開範囲を混同しない。

## テストの順序

1. Issue #1の成立実証後、Sites版の業務要件、APIに関係する**OpenAPIのoperationId**、DBスキーマ、[Sites固有のケースID](sites-test-cases.md)とコミットSHAを固定する。画面ケースは画面ID、移行・復元は手順ID、外部配送は構成IDと証跡へ対応付ける。OpenAPI未作成のままIssue #9を合格としない。
2. 職員限定アクセスと作成者編集、画像の非公開参照を匿名・他職員・作成者で試す。
3. D1で競合・版確定・冪等・マスタ予約・ロールバックを実DBで試す。[D1退避・復元手順](sites-implementation-scope-review-2026-10-22.md)に従い、書込停止後の論理スナップショットを非公開の検証用Cloud Storageへ保管し、元とは別の検証Site/D1に復元して件数・ハッシュ・R2参照を照合する。Sites管理のD1でCloudflareの直接エクスポート・Time Travelを使えるとは未確認のため、これに依存しない。
4. R2でアップロード、上書き拒否、複数ページ一覧、指定削除、孤立ファイル回収、保護すべき送信済み版の保持を確認する。保存済みファイル件数と日次処理時間を記録する。
5. 専用ChatworkルームへMarkdown本文、`.md`、PDF、画像を送り、投稿IDとファイルIDを版IDに結び付けて照合する。部分成功・応答喪失・5分後の照合・手動確定を別ケースで試す。
6. [案Aの非同期構成](sites-async-review.md)に基づき、Cloud Tasksの個別配送・5分後照合、Cloud Schedulerの毎分監視・日次期限処理をCloud Runワーカーで検証する。Cloud RunからSite内部APIへのサービス認証、ジョブ確保、R2転送、D1結果保存、投稿用アクセストークンの取得、重複呼出し、停止からの復帰を測る。
7. [KIIYAデモの参照方針](ui-reference.md)に従い、参照版を固定してモバイル実機で画面配置、ドラムピッカー、客室切替、未入力案内、時刻編集、報告確認を比較する。オフライン入力・同期、画像、アーカイブ、日付変更も確認し、デモとの意図的な差異を記録する。

各ケースを`合格／不合格／未実施`で記録し、未実施を成功として扱わない。[Sites版ケース](sites-test-cases.md)は新構成の固有条件、既存の[テストケース](baseline/test-cases.md)は業務シナリオの基準とする。API操作をSites版OpenAPIへ、画面・移行・復元・外部配送をそれぞれ画面ID・手順ID・構成IDと証跡へ結び付ける。

## 観測と復旧

外部API呼出し、報告ID、版番号、成果物番号、非同期実行ID、送信結果、D1/R2期限処理件数、所要時間を個人情報を含めず記録する。`Unknown`は重複送信を避けるため自動再送しない。復旧演習ではD1とR2の整合、送信済みChatwork投稿との照合を行う。タイムアウトやメモリ上限は実測で設定し、想定件数の増加で再測定する。
