# Chatwork連携を実務で使う前の決定・確認事項（2026-10-27）

この記録は、本番運用に向けた判断事項を整理する。検証用ルームへの本文1件のテスト投稿は到達を確認したが、報告全体の自動送信と本番用ルームの受け入れは未完了。実装・受け入れの詳細は[Chatwork画面・配信契約](chatwork-screen-and-delivery.md)、[本番設定API](chatwork-production-settings-api.md)、[受け入れケース](sites-test-cases.md)を正本とする。

## 決定済みの方針

- 投稿元はアプリの送信設定1件に固定した、既存メンバーのChatworkアカウント1件とする。各職員のChatwork認証は不要。作業・報告の操作者はSites側の職員IDで記録する。
- 本番room IDは`manage_chatwork`権限のある設定担当職員が画面で入力する。APIから得たルーム名を確認してDBへ確定し、そのルームへの確認投稿を人が照合する。開発者へのroom ID伝達や環境変数編集を運用手順に含めない。
- 検証用ルームでのテスト成功は、本番ルームの権限確認やCloud Run経由の報告送信成功を意味しない。本番送信は送信先確認とワーカー経路の受け入れが揃ってから有効にする。
- 報告確定時の設定版・送信元アカウントID・宛先room IDをジョブへ固定する。設定変更で別ルームに無断送信しない。投稿結果不明は自動再送せず照合する。
- OAuth更新トークンは暗号化してSite側に保存し、Cloud Runへ渡さない。認可失効、送信元変更、ルーム権限喪失時は送信を停止する。

## 実務開始前に担当者と決めること

| 項目 | 決める内容 | 状態 |
| --- | --- | --- |
| 投稿元アカウント | 実務で使用するChatworkアカウント、管理者、退職・利用停止時の再接続担当。表示名だけでなく`account_id`で固定する。 | 要確定 |
| 業務報告ルーム | 本番room IDを入力・確認する担当、画面上で確認するルーム名、初回確認投稿を照合する担当。room IDやトークンは公開Issueに記載しない。 | 要確定 |
| 設定権限 | `manage_chatwork`を持つ主担当と代行者、権限付与・剥奪を行う職員管理者、担当者不在時の対応。 | 要確定 |
| 報告内容 | Markdown本文／添付の選択、PDF・画像の必要成果物、実際の報告書の見え方と受領側の確認担当。 | 要確定 |
| 障害時の運用 | `Failed`・`Unknown`・権限失効・ワーカー停止を誰がいつ確認し、手動照合・再接続・送信停止を行うか。結果不明を自動再送しない原則は確定済み。 | 要確定 |
| 本番利用開始 | 業務ルームの確認投稿、Cloud Run経由の成果物送信、異なる職員2名から同じ投稿元への送信、トークン更新、失敗系の証跡を誰が判定して利用を許可するか。 | 要確定 |

## 受け入れで残す証跡

検証・本番を分け、実施日、担当者、配備版、設定版、送信元`account_id`、ルーム名、報告ID、成果物別の投稿ID、Chatwork画面での到着確認、失敗時の状態を非公開の運用記録に残す。秘密値と業務room IDを公開リポジトリに書かない。[Issue #5の手動試験TODO](../issues/05-worker-chatwork.md)と[Sites受け入れケース](sites-test-cases.md)の`SITE-CHATWORK-*`、`SITE-JOB-*`を完了条件に使う。
