# Sites版UIの参照元

Sites版の現場向け画面は[KIIYAデモ](https://kiiya-cleaning-demo.hherocl278.chatgpt.site/)を外観と操作の参考にする。ローカルの`kiiya-demo-site`（確認時のコミット`f5ce882`）と[デモv14に基づくUI設計](baseline/ui-design-v14-2026-10-16.md)で、以下の要素を確認した。公開URLの現時点の配備版との一致は未確認のため、実装時には参照したデモ版と画面記録を固定する。

| 画面・部品 | 参考にする表示と操作 |
| --- | --- |
| 全体 | スマートフォン幅の縦長画面、深緑を基調とするカード、4ステップの進捗、画面下部の固定操作バー |
| 今日の作業 | 担当・作業日を先に確認し、作業開始後に清掃範囲へ進む流れ |
| 清掃範囲 | 203〜206号室の選択と宿泊情報、トイレ・シャワーの独立したドラムピッカー。中央の値を選択中として示し、上下スワイプ後に整数へ揃える |
| 全体チェック | 同じ画面内で客室番号を切り替え、客室チェック、ユニット別作業カード、共通入力を縦に確認する配置 |
| 入力不足 | 報告操作付近の未入力件数の吹き出し、該当客室・項目への移動と強調、その他の不足一覧 |
| 作業完了後 | 無効化した「完了」と、その左の「時刻編集」。報告本文のプレビュー・編集・送信確認までの操作順 |

デモはUI参照であり、保存・認可・送信の正しさを証明する資料ではない。デモ内に残る旧表示の「洗面周り床」、独立したトラブル欄、客室単位の単純な不備チェックはSites版へそのまま移さない。新版の10作業、**洗面周り廊下**、備考とID付き不備の区別、客室ゼロ件などは[業務要件](requirements.md)と[本番画面構成](baseline/production-screen-flow.md)に従う。Siteのログイン表示はSitesの本人確認方式に合わせる。

Issue #7では、参照版を固定したデモと同じ操作順をモバイル実機で比較する。ドラムピッカー、客室切替、未入力案内、時刻編集、報告までを通し、差異と意図的な変更を記録する。オフライン同期やサーバー認可は別の受け入れケースで判定する。
