# 案Aの採用方針と検証条件

2026-10-22、案A（SitesのD1/R2をデータの正本とし、Cloud Run専用ワーカーがChatwork投稿・非同期処理を実行）を実装・検証の方針に選んだ。ChatworkのOAuthとトークン更新はSite側だけが担当する。Cloud Runは確保済みジョブの投稿用アクセストークンだけをSite内部APIから取得する。案Bは採用していない。以下を検証せずに本番切替はしない。

| 条件 | 決定・検証する内容 | 止まる作業 |
| --- | --- | --- |
| 職員の本人確認 | MVPは職員が各自のChatGPTアカウントを使うよう人の運用で管理し、共通利用のアプリ検知は設けない。職員登録・利用停止と全職員閲覧の境界、既存Google IDからの移行時の対応付けは確認する | 実データ移行、認可の受け入れ |
| Siteの公開範囲 | 職員限定のSiteとして運用する方法。GitHub publicとは別に決める | 実データを持つSite公開 |
| 非同期実行 | 個別遅延はCloud Tasks、毎分・日次はCloud SchedulerからCloud Runを起動する。Cloud RunからSite内部APIへの認証、ジョブ権限、障害復帰、費用を検証する | Chatwork報告の統合受け入れ |
| D1の整合性と容量 | 版確定・作業更新・冪等・マスタ予約を原子的に扱えるか。現行データ量、復元、移行速度 | DB移行、本番切替 |
| Workerの実行限界 | Site側の画像圧縮・PDF生成とCloud Run側のChatworkアップロードのメモリ・時間・サイズ。R2からのファイル転送も実測する | 報告・画像の受け入れ |
| Chatwork OAuth | Siteのコールバック、ホスト済みシークレット、D1への暗号化保存、Siteだけでの更新・再接続、確保済みジョブへのアクセストークン受渡し、検証ルーム権限 | 実投稿 |
| R2の期限処理 | 一覧・削除の権限、件数増加時の時間、孤立ファイルの回収、復元方法 | 保存期限の受け入れ |

既存GCP構成の設計決定を、この仮定リポジトリの作成だけで取り消さない。採用判断は検証環境の結果と費用・運用負担を比較して記録する。
