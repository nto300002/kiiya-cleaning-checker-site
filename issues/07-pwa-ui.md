## 目的
KIIYAデモの外観・操作を参考に、現場向け4ステップ画面をSites版PWAとして実装する。

## 作業
- 当日作業、対象範囲、全体チェック、報告、設定・アーカイブをスマートフォンで実装する。
- トイレ・シャワーのドラムピッカー、S03内客室切替、10作業カード、未入力案内、備考・鍵・シーツメモ、画像入力を含める。
- オフライン下書き、再接続後の同期、更新番号の競合確認を実装する。
- `docs/ui-reference.md`のデモ参照版を固定し、画面と操作の差異を記録する。業務規則はSites版要件と本番画面構成に従い、デモに残る旧表示を移植しない。
- 設定画面に`manage_chatwork`保有者向け「Chatwork接続」を設け、送信元のアカウントID・表示名、送信先のroom ID・ルーム名、接続状態、最終確認時刻、再接続・宛先再確認の操作を表示する。秘密値は表示しない。一般職員にはChatwork OAuth操作を求めない。
- 最初の画面で本番room IDが未設定なら、清掃入力より先に送信先設定の案内を表示する。設定担当職員には「Chatwork連携を設定」ボタンからroom ID入力・ルーム名確認へ進め、一般職員には設定担当職員への連絡を案内する。清掃記録と報告プレビューは利用可能にし、本番送信だけ止める。状態取得失敗は未設定と断定しない。
- 最初の画面と本番設定画面は`docs/chatwork-production-settings-api.md`の職員向け読み取り・`manage_chatwork`保有者向け操作を使う。候補ルーム名の確認前に本番宛先を変更せず、テスト投稿が届いたことを人が照合するまで送信先確認済みと表示しない。
- 設定画面全体はIT担当者限定にしない。一般職員が使うアーカイブ導線を維持し、Chatwork連携欄だけ`manage_chatwork`保有者に表示する。報告確認には確定済み投稿元名・宛先ルーム名・利用状態・不透明な設定版だけを読み取り表示し、送信元ID・room ID・秘密値・変更操作は返さない。
- Issue #10の既存本番Site内の期限付き試験状態、本番業務報告ルームの`DestinationVerified`（送信先確認済み）、Cloud Run経路まで利用可能な`DeliveryEnabled`（報告送信可）を画面上で分ける。報告確定後の「送信待ち」は送信成功と表示せず、設定変更で保留されたときは旧・新の宛先と既投稿の有無を再確認できる案内を出す。
- 部分送信を元の宛先で続けないときは、IT担当者の確認済み`Failed`と、照合中の`Unknown`を別表示する。作成者には旧ジョブの終了結果と新版作成への導線を示し、既投稿IDや未投稿分の詳細な確認・終了操作はIT担当者向けにする。

## 完了条件
- [ ] モバイル実機でデモと画面の配置・操作順を比較し、ドラムピッカー、客室切替、未入力案内、時刻編集、報告確認の挙動と意図的な差異を記録する。
- [ ] 日付変更で当日画面が新規入力になり、前日の保存済み記録はアーカイブに残る。
- [ ] 対象室ゼロ件と全室アメニティのみの必須判定が業務要件どおり。
- [ ] 宿泊人数0人を全客室種別で入力できる。0人室ではアメニティ・枕・設置場所のチェックを隠し、アメニティセットの対象から外す。通常・連泊清掃の清掃項目は残し、連泊アメニティのみの0人室は個別チェックなしで職員最終確認を必須にする。人数変更時の再確認、混在・全室0人、未解消不備、報告への反映を`SITE-UI-03`で確認する。
- [ ] 未同期内容を端末変更や競合時に無断で上書きしない。
- [ ] `manage_chatwork`保有者だけが本番Chatwork接続・送信先確認を操作できる。一般職員の設定画面にOAuth操作やトークンを出さず、認可失効・ルーム権限喪失は送信停止として示す。
- [ ] 送信先未確認で手動停止した際は確認投稿も不可と表示し、未投稿確認ジョブの取消理由を示す。経路正常で停止解除後は新しい確認投稿を案内し、本番報告は人の照合まで無効にする。権限剥奪による未適用変更・未投稿ジョブの終了は新しい設定担当者が履歴で確認できる。
- [ ] 本番room ID未設定時、最初の画面に役割別の案内が出る。設定後の再取得で案内が消え、一般職員にはroom IDそのものを表示しない。通信失敗時は状態確認不能と示し、送信可能と誤表示しない。
- [ ] 一般職員がアーカイブ導線を利用でき、Chatwork詳細・変更APIは403になる。報告向け読み取りAPIは確定済みの投稿元名・ルーム名・利用可否・不透明な設定版だけを返す。
- [ ] 検証用ルームの成功だけでは報告ボタンを本番送信可にせず、業務報告ルームでの権限確認後もワーカー経路の受け入れが終わるまで送信不可と示す。受付、送信済み、結果不明、設定変更による保留、期限切れを区別する。
- [ ] 部分送信保留からIT担当者が理由付き`Failed`へ確定すると作成者に新版作成を案内し、成否不明なら`Unknown`と照合待ちを表示する。職員画面から旧ジョブの`Sent`・`Failed`を任意に切り替えられない。
